Files and environment

ThinkRail keeps its own state in one directory, ~/.thinkrail. Everything that belongs to pi (credentials, chat transcripts, MCP configuration) stays in pi’s own directory, ~/.pi. This page lists both, plus the installer’s files, ports, and environment variables.

Warning

Unverified: the location of the desktop app’s own per-user data directory (see Desktop app files) is chosen by the Electrobun framework and was not confirmed from the repository.

Directories at a glance

Section titled “Directories at a glance”
LocationOwnerPurpose
~/.thinkrail/ThinkRailApp state: projects, workspaces, settings, review comments, logs. Move it with THINKRAIL_DATA_DIR.
~/.thinkrail/worktrees/ThinkRailThe git worktrees behind your workspaces.
~/.pi/agent/piCredentials, models, chat transcripts, MCP config, prompt templates. Move it with PI_CODING_AGENT_DIR.
<workspace>/.thinkrail/context/ThinkRailPer-workspace scratch files, ignored by git.
<repository>/.pi/piProject-level pi resources: settings, prompts, MCP servers, subagents, extensions.
~/.config/thinkrail/install.jsonInstallerRecords how the CLI was installed.
~/.cache/thinkrail/CLI binaryFiles unpacked from the installed binary.

On Windows, ~ is your user profile folder (%USERPROFILE%).

~/.thinkrail

Section titled “~/.thinkrail”

ThinkRail creates this directory on first use. Files are JSON unless noted. If a state file cannot be read, ThinkRail sets the file aside as <file>.corrupt-<timestamp> and starts from empty.

PathContents
config.jsonHost-wide settings: theme, analytics choice, notifications, terminal options, composer size, line widths, favorite and recent models, default and review models, subagent options, JetBrains AI quota options, settle days, disabled extensions, custom layouts. See Settings reference.
projects.jsonKnown projects: open or closed, slug, trust decisions, skill and MCP approvals.
workspaces.jsonWorkspace records: name, branch, worktree path, base branch, last activity, per-workspace overrides.
terminals.jsonThe list of terminal tabs per workspace. Running shells do not survive a host restart; the tabs do.
session-lifecycle.json, session-receipts.json, turns.jsonBookkeeping for chat completion and unread state, and the per-run change sets behind Agent turns. Chat transcripts are not here.
reviews/<workspace-id>.jsonLocal review comments for a workspace.
reviews/archive/<workspace-id>/<review-id>.jsonReviews archived by Clear review.
delegation/Subagent child sessions, grouped by workspace.
worktrees/<project-slug>/<branch>/The git worktree for each ThinkRail-created workspace.
installation.jsonA random installation ID, used for analytics. It is not sent as a file and holds no account information.
attribution.jsonA record of whether the one-time “how you found ThinkRail” link was attempted. Expires after 30 days.
feedback.jsonCounters for the interview invitation.
logs/Log files, described under Logs.

Workspace worktrees

Section titled “Workspace worktrees”

A workspace you create from a project gets its own git worktree:

<project-slug> is the project’s stable slug and <branch> is the workspace’s branch name, a short kebab-case slug. The Default workspace is not a worktree: it is the project’s own folder. An existing worktree you attach stays where it is.

Removing a workspace deletes its worktree, including uncommitted work, but keeps the git branch. See Manage workspaces and Workspaces and isolation.

Inside a workspace

Section titled “Inside a workspace”

Each workspace has a scratch folder, .thinkrail/context/, with a .gitignore containing *, so it never shows up in your changes. It holds temporary files such as:

PathContents
.thinkrail/context/todos/<session-id>.jsonThe plan (TODO list) for a chat.
.thinkrail/context/todos/<session-id>.baselines.jsonBaselines used to compute per-step changes.
.thinkrail/context/TASK-<slug>.mdTask specs written by the brainstorming workflow.
.thinkrail/context/pr-body.mdPull request body drafts.
.thinkrail/context/pr-shots/Screenshots staged for a pull request.

pi files

Section titled “pi files”

pi stores its state under its agent directory, ~/.pi/agent by default. Set PI_CODING_AGENT_DIR to the directory itself to move all of it. ThinkRail reads and writes these files through pi and never keeps copies.

PathContents
~/.pi/agent/auth.jsonProvider logins and API keys.
~/.pi/agent/models.jsonCustom models and per-model context windows.
~/.pi/agent/settings.jsonpi settings, including installed pi packages.
~/.pi/agent/sessions/Chat transcripts as JSONL, one folder per working directory. ThinkRail rebuilds a chat from here after a reload or restart.
~/.pi/agent/prompts/Global prompt templates (Settings → Prompt templates).
~/.pi/agent/mcp.jsonUser-level MCP servers.
~/.pi/agent/mcp-auth.jsonOAuth tokens for MCP servers.
~/.pi/agent/mcp.logMCP server messages.
~/.pi/agent/trust.jsonSaved project-trust decisions made through pi.
~/.pi/agent/extensions/User-installed pi extensions. JetBrains AI adds jetbrains-central.ts here through the central CLI.
~/.pi/agent/agents/Personal subagent definitions.
~/.pi/web-search.jsonOptional API keys for web research providers. It moves to $PI_CODING_AGENT_DIR if that is set, or to $XDG_CONFIG_HOME/pi if only XDG_CONFIG_HOME is set.

Inside a repository, pi and ThinkRail read project resources from <repository>/.pi/: settings.json, prompts/, mcp.json, agents/, extensions/, and skills/. These load only when the project is trusted. See Trust a project.

Skill locations read in place

Section titled “Skill locations read in place”

ThinkRail also reads skills that other agents use, without copying them:

PathNotes
~/.agents/skills/Personal skills shared across agents.
<project>/.claude/skills/, <project>/.github/skills/, <project>/.gemini/skills/Project skills from other agents.
~/.claude/skills/ (or $CLAUDE_CONFIG_DIR/skills)Claude user skills, plus skills from installed Claude plugins.
~/.codex/skills/ (or $CODEX_HOME/skills)Codex user skills.
~/.copilot/skills/Copilot user skills.
~/.gemini/skills/ (or $GEMINI_CLI_HOME/.gemini/skills)Gemini user skills.

See Use existing skills.

Installer and CLI files

Section titled “Installer and CLI files”
PathContents
<prefix>/bin/thinkrailThe CLI binary. thinkrail.exe on Windows. The default prefix is ~/.local.
~/.config/thinkrail/install.jsonChannel, version, tag, prefix, whether the installer added the Windows PATH entry, and the install time. Read by thinkrail update and thinkrail uninstall. On Windows: %USERPROFILE%\.config\thinkrail\install.json.
~/.cache/thinkrail/The installed binary unpacks its web app, skills, and runtime helpers here, under a folder per kind and version. $XDG_CACHE_HOME/thinkrail if XDG_CACHE_HOME is set.
Shell startup fileOn macOS and Linux, a block between # >>> thinkrail PATH >>> and # <<< thinkrail PATH <<< in ~/.bashrc (~/.bash_profile on macOS), .zshrc (in $ZDOTDIR if set), or ~/.config/fish/conf.d/thinkrail.fish.

Desktop app files

Section titled “Desktop app files”

The desktop app keeps the same ~/.thinkrail state as the CLI. It also keeps two small files for the window itself, routes.json (the last route per window) and preferences.json, in the per-user data directory the framework provides. Set THINKRAIL_DESKTOP_USER_DATA to change that directory.

Warning

Unverified: the default location of that directory on each OS.

The desktop app, the CLI, and a source checkout do not lock each other out of ~/.thinkrail. If you run more than one against the same directory, their changes to shared files are not coordinated and can overwrite each other.

Logs

Section titled “Logs”
PathContents
~/.thinkrail/logs/thinkrail.<date>.<n>.jsonlStructured JSON log lines. A new file starts each day and whenever a file reaches 10 MB. ThinkRail keeps the active file and 14 older ones. Secrets such as tokens and API keys are redacted.
~/.thinkrail/logs/crash.logPlain-text report of a fatal error, appended before the process exits.
~/.pi/agent/mcp.logMCP server messages, owned by pi.

The terminal shows the same log lines in a readable form. The default level is info; run thinkrail --verbose or set THINKRAIL_LOG_LEVEL=debug for more. Output that pi or an extension writes with console.* is intentionally not written to the log files.

Ports and network

Section titled “Ports and network”
WherePortNotes
CLI host24242Change with --port or THINKRAIL_PORT. If the port is taken, the host scans upward for a free one.
Desktop appA random loopback portBound to 127.0.0.1 on port 0 at each launch and never saved.
Source checkout (bun run dev)24242 for the host, 24269 for the web dev serverChange with THINKRAIL_PORT and THINKRAIL_WEB_PORT.

The CLI binds localhost unless you pass --host. The host has no sign-in screen, so keep it on a loopback address or a network you trust.

Outbound connections the host makes:

DestinationPurpose
Your model providersAgent requests, through pi.
api.github.com and github.comRelease checks for updates (CLI and desktop). Also used by the installers to download binaries.
PostHog (EU endpoint)Usage analytics, in release builds only. See Privacy and analytics.
Web search providersThe agent’s web research tools.
raw.githubusercontent.comInstaller scripts and downloads.
thinkrail.aiA one-time attribution link, opened in your browser.
MCP servers you configureTool calls to those servers.

The full list, with what is sent and how to turn each off, is in the Security and data overview.

Variables the host reads from your system

Section titled “Variables the host reads from your system”
VariableDescription
HOME, USERPROFILEHome folder (USERPROFILE on Windows). Base of ~/.thinkrail and ~/.pi.
PATHWhere the host finds git, gh, central, and editors. At startup the host merges in the PATH from your login shell, so tools installed through shell profiles are found when the app starts from the Dock or a launcher.
SHELLThe shell for new terminal tabs. When set, it wins over Settings → Terminal → Windows shell.
SSH_AUTH_SOCKOn macOS, if it is missing, the host reads it from launchctl so git can use your SSH agent.
LANG, LC_ALL, LC_CTYPEIf none is set, the host sets a UTF-8 locale so child processes behave.
DISPLAY, WAYLAND_DISPLAYOn Linux, a graphical session is required for the folder picker.
CI, NODE_ENV=testTurn analytics off.

Variables from your login shell that start with PI_ or THINKRAIL_ are never imported, so set those in the environment that launches ThinkRail.
