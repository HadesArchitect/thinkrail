Make your first change

In this tutorial you install ThinkRail, let the agent add a Quick start section to a README in one of your GitHub repositories, review the diff, and open a pull request. Along the way you meet the pieces you use every day: workspaces, chats, steering, the Changes review, and Open PR.

Before you start, make sure you have:

  • About 20 minutes.
  • macOS on Apple Silicon, Linux, or Windows. See Platform support.
  • git on your PATH.
  • A GitHub repository you can push to, cloned locally, with origin pointing at GitHub. Any small project with a README.md works.
  • A model provider: a JetBrains AI account, or an API key or subscription for a provider such as Anthropic or OpenAI.
  • Optional: the GitHub CLI (gh), signed in with gh auth login. Without it, ThinkRail opens GitHub’s compare page for you to finish the pull request.

Install and launch

Section titled “Install and launch”

1. Install the thinkrail CLI

Section titled “1. Install the thinkrail CLI”

Run the installer in a terminal. On macOS or Linux:

On Windows, from cmd or PowerShell:

The installer downloads the binary for your platform, verifies its checksum, and puts thinkrail on your PATH. It finishes by printing Run: thinkrail. Open a new terminal so the updated PATH takes effect.

Tip

Prefer a native window? The desktop app runs the same host. See Install ThinkRail for the desktop app, release channels, and other install options.

2. Launch ThinkRail

Section titled “2. Launch ThinkRail”

The terminal prints thinkrail → http://localhost:24242 and your default browser opens that address. If port 24242 is busy, ThinkRail picks the next free port and prints that URL instead. Keep the terminal open: it is running the host.

3. Choose what usage data to share

Section titled “3. Choose what usage data to share”

A Help improve ThinkRail dialog appears first. It explains that ThinkRail never collects prompts, code, files, credentials, or account identity. The Share additional usage data switch is on. Leave it on or turn it off, then click Done.

You see the Welcome screen with a warning: “No model provider connected — the agent can’t run.”

You can change this choice later in Settings → Privacy. Read Privacy and analytics for exactly what is sent.

4. Connect a model provider

Section titled “4. Connect a model provider”

Click Connect a provider in the warning. Settings opens on the Providers page. Connect the provider you have:

  • JetBrains AI. The JetBrains AI card shows how to install the JetBrains Central CLI (central) if it is missing. Run the command it shows in a terminal, click Recheck, then click Connect. If the card says Central is signed out, click Sign in and finish in the browser.
  • An API key. Under Available, find your provider and click API key. Paste the key and click Submit.
  • A Claude, ChatGPT, or Copilot subscription. Under Subscriptions, click Sign in next to the provider and finish in the browser.

The provider moves to the Connected section. Press Esc to close Settings; the warning on the Welcome screen is gone.

For details on each option, see Connect a model provider.

Start the work

Section titled “Start the work”

5. Open your project

Section titled “5. Open your project”

On the Welcome screen, click the Open project card, then choose Open project from the menu. Pick the folder of your cloned repository.

ThinkRail adds it to the Projects tool on the left and shows the project’s home: its name in large type and a row of cards, including Start building and Work in project folder. A repository without specs in its project folder also gets a Set up project card first; that is the card from Describe your project, and this tutorial works with or without it.

Tip

If a project trust notice appears, leave the project untrusted for now. Nothing in this tutorial needs it. See Trust a project.

Note

Screenshot to add: the project home with the Set up project, Start building, and Work in project folder cards.

6. Create a workspace with your task

Section titled “6. Create a workspace with your task”

Click Start building. The Create workspace dialog opens with Isolated workspace selected and From set to the branch you have checked out, usually main.

In What do you want to work on?, type:

The dialog notes that ThinkRail will name the workspace and branch from your request. Click Create.

ThinkRail creates a git worktree on a new branch under ~/.thinkrail/worktrees/, starts a chat in it, and sends your message. The new workspace appears under your project in the Projects tool, and the chat opens in the center with your message at the top. Your own checkout and branch are untouched.

7. Watch the agent work

Section titled “7. Watch the agent work”

The chat streams as the agent works. A status line reads “Thinking…”, “Running read…”, or “Writing…”; routine tool steps fold into compact activity groups you can expand.

Early on, the agent names the work. The workspace in the Projects tool and the top bar changes from workspace-1 to a short descriptive name, and the branch gets a matching slug. While the agent runs, the workspace row shows a working badge, and the chat header shows token use and cost as pi reports them.

Note

If the agent needs a decision, it shows a card that reads “Your input is needed — the agent is waiting.” Pick an option and click Submit. A card with several questions has a Next → button that leads to a Review & submit step, where Submit sends all your answers.

8. Steer the agent

Section titled “8. Steer the agent”

While the agent is still working, type this in the message box:

The send button reads Steer. Press Enter. A Steering: row appears above the message box and stays there until the agent picks the message up at its next step, so you don’t have to wait for the turn to end or stop it.

If the agent finished before you got here, press Enter anyway: the message goes out as a normal message and the agent revises the section.

Tip

Cmd/Ctrl+Enter queues a follow-up for after the agent finishes instead, and Stop ends the turn. See Steer and queue messages.

Review the change

Section titled “Review the change”

9. Open the diff in Changes

Section titled “9. Open the diff in Changes”

When the agent finishes, its last message summarizes what it did. If you looked away, a green dot on the workspace row tells you the result is waiting.

Open the Changes tool from the right rail. The scope reads All changes, and README.md is listed with its +N −M line counts. Click it. A Changes review tab opens in the center with the diff of the new section.

Tip

If you only wanted to see what the agent changed, you can stop here. The change lives in the workspace, not in your project folder. To throw it away, see Undo or discard changes.

10. Leave a review comment and send it

Section titled “10. Leave a review comment and send it”

Hover over a line in the new section and click Comment on this line in the gutter. In the box that opens, type:

Click Save draft. The comment appears as a draft card on that line, and the review tab’s toolbar now shows Send review (1). Click it.

ThinkRail sends the comment, with the quoted line and its context, to the chat as one structured message. In the chat it appears as a compact card that reads “Sent 1 review comment on README.md”. The agent revises the file and can mark your comment resolved. The Review tool on the right tracks the comment’s status.

11. Keep the hunks you accept

Section titled “11. Keep the hunks you accept”

Back in the review tab, which updates as the agent edits, read the revised diff. Click Keep on each hunk you accept. When you keep the last hunk, the file is marked viewed and the bottom bar reads “1 of 1 reviewed”.

Keeping is your review state: it records that you read and accepted the change. If you disagree with a hunk, Revert hunk undoes it in the worktree and Ask agent about this hunk starts a comment anchored to it. See Review changes.

Note

Screenshot to add: the Changes review tab with a draft comment on a line and the Send review (1) button in the toolbar.

Ship it

Section titled “Ship it”

12. Ask the agent to commit

The change is still uncommitted in the workspace. Send this message in the chat:

The agent runs git commit in the workspace. The commit now appears under Commits in the Changes scope menu.

13. Open the pull request

Section titled “13. Open the pull request”

Open the TODO List tool from the right rail and click Open the plan page, the document icon next to “Queue a task for the agent”. A plan tab opens for this chat. Click Open PR in its header.

The Open PR dialog shows a Title, taken from the chat title, and a Description rendered from the chat’s plan, including a section that lists your commit. Edit either if you like, then click Open PR.

ThinkRail pushes the branch to origin and creates the pull request against the branch you started from. A “PR opened” message confirms it, and the pull request number appears next to the button.

If gh is not installed or not signed in, ThinkRail still pushes the branch and opens GitHub’s compare page in your browser with the title and description filled in; click Create pull request there. A dialog explains how to set up gh so the next PR opens in one click. If the push itself can’t authenticate, a Git push couldn’t authenticate dialog lists the commands that fix it. See Open a pull request.

Merge the pull request on GitHub when it is ready. ThinkRail has no merge button of its own; after the pull request merges, the workspace moves to its project’s Settled shelf on its own.

What you built

Section titled “What you built”
  • An isolated workspace: a git worktree on its own branch, with its own chat, changes, and terminal, while your checkout stayed as it was.
  • A reviewed change: you steered the agent mid-turn, left an anchored comment that went back to the agent as structured context, and kept the hunks you accepted.
  • A pull request whose title and description came from the chat, opened without leaving ThinkRail.
